一、最应先修的三处图示错误

E01 · 优先修正Big-O 曲线与自己的结论相反

src/images/alg-bigo-curve.svg:25–35、50；src/algorithms/big-o.md:158

正文与图注说“log n 几乎还贴着地板”，但图中绿色对数线在大部分区间高于红色平方线；到 n=30，三线终点 y 分别为 60、60、66，几乎都贴顶部。共用“操作次数”纵轴，却将曲线分别缩放，无法比较大小。

建议：统一尺度绘制具体函数 n²、n、log₂n，并标注数值；如需显示相对增速，另画归一化图，不沿用操作次数纵轴。

E02 · 优先修正归并排序图凭空增加了一个 5

src/images/alg2-merge.svg:22、54–61、67–68

输入 [38,27,43,3,9,82,10] 只有 7 个元素，输出却为 [3,5,9,10,27,38,43,82]，变成 8 个。右侧两半结果也不对应左侧拆分。

建议：两半改为 [27,38,43] 与 [3,9,10,82]，最后合成 [3,9,10,27,38,43,82]。同步修改比较说明。比较规则的最后两行还发生重叠，应一起排版修复。

E03 · 优先修正二分查找把“中点下标”写成“中点值”

src/images/alg-binary-search.svg:34、54、74

图中文字出现 mid=17 ... low=mid+1=5，逻辑上相当于 17+1=5。三轮真实状态是 (mid, arr[mid]) = (4,17) → (7,34) → (5,23)。

建议：分别标出下标和元素值；更新边界只用下标，比较大小才用元素值。同步拉开步骤标题、指针和图例，减少重叠。

二、概念与参考输出仍有错误

E04// 不是“砍小数”

src/foundations/operators.md:48、54

实测 -10 // 4 == -3，而 int(-10 / 4) == -2。当前措辞把向负无穷取整与朝零截断混为一谈。

建议：改为“地板除，向下取整”，补一组负数对照。

E05round 不能概括为“逢五进一”

src/foundations/variables.md:147、294

当前称 round() 是四舍五入。实测 round(2.5)=2、round(3.5)=4，恰好中点取偶数。

建议：说明舍入规则，避免把普通口语规则当作精确 Python 语义。

E06global 旧错误残留在速查表

src/functions/scope-recursion.md:256、283–284；src/appendices/appendix-b.md:178

表中把函数内 total += 1 未声明 global 解释为“改的是新建的局部变量，全局没动”。实测会先触发 UnboundLocalError。

建议：区别 total = 1 的局部绑定与 total += 1 的先读后写；同步正文、FAQ 与附录。属于同类错误的残留副本，不是已修正文再次出错。

E07排行榜冠军输出写错

src/data-structures/dictionaries.md:249、253、266

小明先进入字典，随后与小红并列 80 分。原代码 max(..., key=...) 实际选择小明，展示输出却写小红。

建议：修正输出，并说明并列时选先遇到的一项；或明确实现并列冠军。

E08同长度单词的参考顺序写反

src/projects/algorithm-arena.md:517、527、531

题意与代码要求按长度、再按字典序排列，实际输出应为 ['kiwi','pear','apple','banana']，不是 pear 在 kiwi 前。

建议：只修预期输出，不要改正确的排序键 (len(w), w)。

E09中文字符串排序不是拼音排序

src/projects/data-analysis.md:546、554

题目要求按名字“拼音/字母”排列，但答案直接按字符串排序。sorted(['张三','李四']) 得到张三、李四，并非拼音顺序。

建议：改成“字符串顺序，中文不保证按拼音”，或显式提供拼音键。

E10积分门槛只改 while 不够

src/control-flow/while-loops.md:524、532、538

按提示只把循环门槛改成 500，领奖判断仍是 100。输入 100 → 0，退出后仍能领“达标”奖。

建议：用一个 target 同时驱动提示、循环和领奖条件。

E11阶乘循环不变量差一位

src/control-flow/while-loops.md:430–438

每轮末尾已经执行 i += 1，所以 result 应等于 (i-1)!，不是 i!。n=5 时末态 result=120、i=6。

建议：明确观察时刻，修为“轮末 result=1×…×(i−1)”。

E12“打印成功”不能证明前半段没有逻辑错误

src/control-flow/debugging.md:152–156

中点前把剩余票数错算成 100+35，仍会成功打印 135，再在后面触发断言。错误根因在中点之前。

建议：区分“执行到达位置”“异常触发位置”“错误数据产生位置”。二分定位逻辑错误应检查中间状态是否正确。

E13finally 并非输入每轮都执行

src/functions/exceptions.md:243–248、274、281

输入 q 时，程序在进入 try 之前就 return。实测只打印“已退出售票机。”，没有“本轮输入处理完毕。”。

建议：改成“每次进入这个 try 的处理流程，离开时执行 finally”。代码行为没错，讲解范围过大。

三、项目连接、运行闭环与导航问题

E14血量归零仍没有结束文字冒险

src/projects/text-adventure.md:314–323、517、533–538

23.2 要求 hp=0 游戏结束，参考答案只在 go() 内 return。它只结束一次移动，外部 play() 的循环还会继续。

验证：在保留基础 take/open 逻辑的前提下合入扣血分支，执行 east west 三轮使 hp=0，仍可继续输入并通关。即便直接阅读局部片段，也能看到它没有通知主循环结束。

建议：主循环检查死亡状态，或让 go() 返回明确的结束信号。完整给出扩展应该修改的两处位置。

E15排序与查找模块不能按承诺直接连接

src/algorithms/sorting.md:255–273；src/algorithms/searching.md:205–213

排序返回 [(姓名, 身高)]，查找需要 [身高]。实测 find_rank(sort_by_height([('甲',130)]),130) 抛出 tuple 与 int 不能比较的 TypeError。

建议：补充提取身高的连接代码，或统一两边的数据接口，附一段跨章完整运行示例。

E16递归套娃方框并未嵌套

src/algorithms/recursion-divide.md:292、301–315

用坐标探针执行原函数，第一层边界是 x/y∈[-80,80]；第二层却是 x∈[24,136]、y∈[-136,-24]，已经越出第一层。每次从旧角点继续位移，中心会漂移。

建议：固定共同中心，画完回到中心再递归。另有第321行“把模块 A 的 merge_sort 拿来用”指向错误，应指20.3节；代码注释已写对。

E17归并“返回新列表”的承诺有边界例外

src/algorithms/recursion-divide.md:127–128、176、458–459

基线 return arr 在空列表与单元素列表上返回原对象。实测 a=[]; b=merge_sort(a); b.append(7) 后 a 也变成 [7]。

建议：两份实现的基线都返回 arr[:]，或明确共享对象的例外。这不是排序过程修改输入，而是返回值与输入发生别名共享。

E18模块章新题没有完整同步到附录

src/functions/modules.md:525、573；src/appendices/appendix-e.md:160

正文 16.4 已是“双文件模块”，抽奖题已顺延为16.5；附录仍把抽奖列为16.4，遗漏双文件题。

建议：按“题号+题名”校验索引，不能只检查目标章节存在。

E19两个项目工坊锚点失效

src/control-flow/while-loops.md:324；src/control-flow/for-loops.md:372

两条“项目工坊”链接的 fragment 在生成 HTML 的 id 集合中均不存在。章节文件可访问，因此只检查文件存在会漏掉它们。

建议：用实际生成标题 id，或设置稳定显式锚点；把锚点校验加入质量门。

E20uv 文件出现时机与 VS Code 操作顺序不一致

src/getting-started/install.md:273–285、299–319、325–327

刚执行 uv init 就声称“此时”有 .venv 和 uv.lock；官方文档说明它们在后续项目命令阶段生成，而本流程 uv add 已会更新环境，因此也不能说“第一次 uv run 才创建环境”。

此外，终端 cd my_first_uv_project 不会自动把 VS Code 左侧工作区切到该目录。教程先让人在左侧新建 main.py，之后才说打开新项目文件夹，读者可能将文件建在父目录。

建议：按 init → 打开新项目文件夹 → add → 编辑文件 → run 的可见状态重写，每一步只列此时真实存在的文件。默认骨架受 uv 版本影响，标出验证版本，不把旧版本行为当永恒规则。

E21 · 环境条件项可选海龟图仍是文本项目的导入依赖

src/projects/data-analysis.md:134、335、355、391

海龟图调用虽被注释，import turtle 却在顶层。当前受测解释器能运行；在独立进程模拟缺少 _tkinter 后，文本先打印，随后导入报错并以非零退出。

建议：把 import 放入可选绘图函数，确保纯文本路径完全不依赖 Tk。排障表不能对所有 ModuleNotFoundError 一律建议“保留 import turtle”。

四、优化空间：先改善自学闭环，不增加篇幅负担

O01第11–13章仍提前使用函数、回调和 lambda

src/data-structures/tuples-sets.md:246；dictionaries.md:249；nested-data.md:289、317；src/SUMMARY.md:43

第14章才讲函数，但前面项目已连续使用 def、return、key 回调和 lambda；第13章又说下一章才把操作函数化。程序可运行，不等于小朋友能独立解释。

建议：基础路径保留 for 与比较更新的直写版本；封装、回调版本移到第14章之后，或明确标为选读并给最小说明。

O02真实操作截图仍未覆盖最容易卡住的步骤

src/getting-started/install.md:161–209、230–338；src/images/alg2-merge.svg:67–68

VS Code 的七张实图已经在正文中，但 Windows Python 安装勾选、macOS安装与 uv 小节仍主要是文字/命令，没有对应逐步实拍；uv 现存图片未嵌入该节。算法图还有规则文字重叠。

建议：用同一个项目名、同一份代码贯穿真实截图，标清当前目录、解释器和输出。缺真实 Windows 环境时明确待补，不用手绘操作界面替代。概念图仍可使用 SVG。

O03CSV 输入契约不完整

src/projects/data-analysis.md:95–105、302–305

给定示例数据能正常通过。扩展到同名学生时，“小明,60”和“小明,100”会静默覆盖为一条100分记录；只含表头时统计函数会因空集合而失败。

建议：明确“非空、姓名唯一”等约束并拒绝不符合条件的输入，或采用学号主键。将重复姓名、空表、空姓名、非法分数加入验收，而非笼统吞掉异常。

O04测试要覆盖“承诺”，不能只覆盖函数正常值

scripts/check_python_semantics.py:289–309；scripts/check_python_examples.py:115–132

20项语义测试实际分布于11个源文件。图、参考输出、项目连接与练习扩展未被充分覆盖。语法脚本只要发现任意 ... 就跳过；内存探针 print('loading...') 后追加非法 if :，整段也被判定为跳过。

建议：用显式元数据标记错误示例/片段；对返回对象、stdout、分支退出、文件契约、图中元素集合、题号题名建立断言；每次发现本报告中的反例就增加回归。不要用20/409直接声称语义覆盖率，因为测试项与代码块不是一一对应。

O05Git 首次使用还缺署名与认证前提

src/projects/next-steps.md:112–126、217、318–323

已配置环境可以执行；空白配置的新手环境会遇到 Author identity unknown。审计仅在隔离配置下进行身份检查，没有创建提交或推送。

建议：补 Git 安装验证、署名/邮箱配置和首次认证说明；注意邮箱隐私，也可明确这是“已配置环境的命令速查”。

O06爬楼梯“大输入通过”需要写出范围

src/projects/algorithm-arena.md:205、219、280–284

题面列出的 n≤40 样例通过；但默认递归限制1000、冷缓存下，记忆化版本 n=1000 会触发 RecursionError。记忆化减少重复计算，不会消除线性递归深度。

建议：明确非负整数和各版本测试上限；改成“在递归深度允许范围内”，大输入采用迭代。此项不把题面已有样例判成失败。

O07密码不应默认 strip

src/foundations/strings.md:245

“密码、用户名比对前先 strip 是标准动作”混淆字段规则。' secret ' 与 'secret' 本来不同，strip 会静默改变凭据。

建议：用户名是否清理空白由产品规则决定；密码默认保留原始输入，若禁止首尾空白，应提示而非暗中改写。

O08练习去重仍有残留

src/getting-started/install.md:422–475、508–535

加练0.B与Problem0.1都要求验证版本；章末Problem0.3仍要求重复创建uv项目并安装另一个库。它们已经不是内嵌“练一练”卡片，但与用户“uv不需要练习、减少机械重复”的目标仍有距离。

建议：版本验证只保留一个真实检查点；uv不再额外换库重做。留下能诊断错误、解释输出或整合项目的练习。
