# 附录 B：常见错误速查表

> 这份索引只汇总当前正式章节中 `Common Mistakes` 的真实条目。当前覆盖 **30 个章节分组、168 条常见错误**。写代码卡住时，先按章节找到相同的错误，再照“立即修正”处理。

## 怎么使用

1. 先根据你正在学习的章节，找到下面对应的表。
2. 看“错误”确认自己踩到的坑，再读“为什么危险”和“立即修正”。
3. **详细例子、完整代码和更多解释，请通过章节标题或新增分组后的回链返回原章 `Common Mistakes`。**

## 第 0 章：安装开发环境：Python + VS Code（Windows / Mac 分讲）

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| Windows 忘勾 PATH | 系统找不到 python 程序 | 重装时勾 "Add python.exe to PATH" |
| Windows 误装微软商店版 | 行为与官方版不一致、易冲突 | 一律用 python.org 官方安装包 |
| macOS 用 `python` 检测版本 | 不能确认 Python 3 是否可用 | 检测版本一律用 `python3 --version` |
| macOS 碰系统自带 Python | 那是系统用的，动不得 | 装独立 Python 3，绝不碰系统那份 |
| 路径带空格却没加引号 | 空格会把命令拆成多段 | 用引号包住路径，如 `cd "C:\我的代码\python practice"`；练习也可放短路径 |

## 第 1 章：你好，Python！

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 引号用成中文引号 | Python 只认英文 `" "` | 切换输入法，用英文引号 |
| `print` 少了括号 | 现代 Python 必须带 `()` | 写成 `print("你好")` |
| 海龟画不出图（在线环境） | 在线环境弹不了图形窗口 | 先练 `print` 版，本地装好再画 |
| 漏写 `import turtle` | 没"请进"工具就用 | 开头加上 `import turtle` |
| 转角角度算错 | 转不够，图形不闭合 | 正方形用 `90`、三角形用 `120` |

## 第 2 章：变量与数据类型

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 把 `=` 当"等于" | `=` 是赋值不是比较，语法报错 | 比较用 `==`，赋值才用 `=` |
| 变量名用数字开头 | 命名规则不允许 | 改成 `first_name` |
| 用中文引号做字符串 | Python 只认英文引号 | 切英文输入法，用 `" "` |
| 忘转类型就相加 | 文字和数字不能加，报错 | 先 `int("14")` 再算 |
| 以为 `int()` 会四舍五入 | `int` 直接截断小数 | 要取最近整数用 `round()`；注意 `round(2.5)` 得 `2`，它不等于"逢五进一" |
| 覆盖内置名称 | `str` 是内置类型名，覆盖后会让 `str()` 不能正常使用 | 改成 `text` 等自定义名；真正的关键字如 `if` 根本不能当变量名 |

## 第 3 章：字符串与文本处理

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 索引从 1 开始数 | 实际 `s[1]` 是 `b`，索引从 0 起 | 记住第一个是 `s[0]` |
| 以为 `.upper()` 改原串 | 字符串不可变，返回新串 | `s = s.upper()` 存回 |
| 切片写成含尾 | 切片"含头不含尾" | 想取到 4 就写 `s[1:5]` |
| 数字直接拼字符串 | 类型不匹配 | `str(90)` 转文字再拼 |
| 索引越界 | 超出长度报 `IndexError` | 先用 `len()` 确认范围 |
| `in` 误当包含关系反了 | 应是"小串 in 大串" | `"Py" in "Python"` |

## 第 4 章：运算符与表达式

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| `=` 当 `==` 用 | `=` 是赋值，不能做判断 | 比较用 `==` |
| 整除与除法混 | `/` 得 `2.5`，`//` 才得 `2` | 要取整用 `//` |
| 取余理解错 | `%` 是余数不是商 | `10 % 4 = 2`（余） |
| `and`/`or` 用反 | 语义反了，判断恒错 | 理清"都要"还是"任一" |
| 优先级漏括号 | 复杂表达式易读错 | 关键处加 `()` 显式分组 |
| 闰年漏世纪年 | 漏了 `%100`/`%400` 特例 | 用完整 `(...) or (...)` 公式 |

## 第 5 章：输入与输出

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 忘了 `input` 返回字符串 | 字符串不能加数字 | `int(input(...))` |
| 把提示语当数据 | 提示只是显示，真值靠你敲 | 真值来自回车后的输入 |
| `split` 转类型漏做的 | 切开仍是字符串 | 各自 `int(a)`/`int(b)` |
| 中文引号写 input 提示 | 报错或乱码 | 用英文引号 |
| 输非数字给 `int()` | 转换失败崩溃 | 确保输数字，或学习 [Chapter 16A](../functions/exceptions.md) 后用 `try / except` 处理 |
| 多值个数对不上 | 解包数量不匹配报错 | 输入个数要和解包一致 |

## 第 6 章：条件判断 if —— 让程序学会"做选择"

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 判断用单等号 `=` | `=` 是赋值不是判断，语法报错 | 改成 `==` |
| `if` 后漏冒号 | 语法要求必须跟 `:` | 末尾加 `:` |
| `elif` 顺序颠倒 | 大分数先命中宽松条件，到不了高级 | 大数条件放最上面 |
| 缩进不齐 | Python 靠缩进分块，错乱就报错或逻辑错 | 统一用 4 空格缩进 |
| `input` 忘了转数字 | 文字不能和数比较，报 TypeError | 套 `int(input(...))` |
| 忘记 `else` 也可能不执行 | 每个 `if` 都会独立判断，可能全跑 | 互斥选项用 `elif` 链 |

## 第 7 章：循环 while —— 让程序"反复做同一件事"

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 漏写"更新"致死循环 | `i` 不变，条件永远真 | 循环体里加 `i = i + 1` |
| 把 `i = i+1` 写成 `i = 1` | `i` 每轮重置，永远不变 | 改成 `i = i + 1` |
| 边界少算一次 | 实际只会取到 1、2、3、4 | 想数 1 到 5 就写 `while i <= 5` |
| `while True:` 忘 `break` | 永远真，死循环 | 在合适的分支里 `break` |
| 哨兵循环只 `input` 一次 | 第二次起用的还是旧值 | 循环前 + 循环尾各 `input` 一次 |
| `break`/`continue` 用错层 | 以为跳出了外层 | 理清要跳的是哪一层 |

## 第 8 章：循环 for 与 range —— 用"迭代"画出整个世界

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 忘 `range` 不含终点 | 实际只有 1,2,3,4 | 写 `range(1, 6)` |
| 想从 1 数到 n 写 `range(n)` | 起点默认是 0 | 写 `range(1, n+1)` |
| 嵌套缩进不齐 | 循环层级错乱 | 内层多缩进 4 格 |
| `print` 忘换行导致挤一行 | 所有内容糊一行 | 内层结束后单独 `print()` |
| 菱形边界重复一行 | 最宽行被打两次 | 用 `range(n-1, 0, -1)` |
| 步长为负却起点<终点 | 正向走不到终点 | 负步长要 `range(5,0,-1)` |

## 第 9 章：调试与调试思维 —— 像侦探一样"破案"

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 看见红字就关窗口 | 放弃了最关键的线索 | 静下心读最后一行错误类型+位置 |
| `while` 条件写 `=` | `=` 是赋值不是判断 | 改 `==` 或 `<=` 等 |
| 文字 + 数字 硬加 | 类型不兼容，TypeError | 用逗号，或 `str(score)` |
| 缩进混用空格和 Tab | Python 认不出对齐 | 统一 4 个空格 |
| `print` 调试后忘删 | 输出被污染、拖累速度 | 定位完就删/注释探针 |
| 名字拼写前后不一致 | NameError | 复制变量名，别手打 |

## 第 10 章：列表 list —— 把一堆东西排好队

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 索引从 1 开始 | Python 索引从 **0** 起 | 第一个用 `names[0]`，最后用 `names[-1]` |
| 编号越界 | 合法编号是 0~3 | 编号必须 `< len(列表)`；取末尾用 `[-1]` |
| 切片端点搞混 | 切片**左闭右开**，不含终点 | 想要到编号 4，写 `nums[1:5]` 或 `nums[1:]` |
| `remove` 找不到值 | 值不存在会 `ValueError` | 先用 `if "阿强" in names` 判断 |
| 把"改"当"增" | 不能改不存在的格子 | 新增用 `append`，改只用已存在的编号 |
| 切片会改原列表 | 切片返回**新列表**，不动原的 | 要改原列表就重新赋值：`nums = nums[1:3]` |

## 第 11 章：元组与集合 —— 有些东西定下就别改，有些事重在"不重复"

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 想改元组 | 元组不可变 | 需要改就用列表 `[ ]`；元组只存定值 |
| 单元素元组漏逗号 | 没逗号就是普通括号分组 | 写成 `t = (5,)` |
| 用 `{}` 建空集合 | `{}` 是字典专属 | 空集合写 `set()` |
| 指望集合保序 | 集合本身无序 | 要去重又保序，用第10章列表法 |
| `remove` 删不存在元素 | 抛 `KeyError` | 用 `s.discard("x")` 更稳 |
| 把列表当集合键 | 列表可变，不能做 key | 改用元组 `d[(1,2)] = 3` |

## 第 12 章：字典 dict —— 像查字典一样，用"名字"直接找到"值"

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 用 `[]` 当字典 | 字典用 `{}`，`[]` 是列表 | 写 `d = {"a": 1}` |
| 查不存在的 key | 抛 `KeyError` 崩溃 | 用 `scores.get("小美", 0)` |
| 以为 `in` 查 value | `in` 只查 **key** | 查值用遍历 `values()` 或列表 |
| 用列表当 key | key 必须不可变 | 改用元组 `d[("a","b")] = 1` |
| 忘记 `items()` 拆包 | 能跑但啰嗦 | 写 `for k, v in d.items():` |
| 遍历时改字典大小 | 遍历中删元素会报错 | 先 `list(d)` 复制 key 再删 |

## 第 13 章：嵌套与结构化数据 —— 把混乱的现实，装进"容器里的容器"

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 套错层就取值 | visitors 是列表，要先取元素 | 写 `visitors[0]["name"]` |
| 忘了内层是可变对象 | 可能 `played` 没初始化成列表 | 建档案时 `played: []` 先备好 |
| 嵌套里直接改报错 | 列表没那么长 | 先确认长度，或改用 `append` |
| JSON 中文变乱码 | 默认 `ensure_ascii=True` | 加 `ensure_ascii=False` |
| 两层循环变量名混 | 覆盖、逻辑错 | 内层换名，如 `for p in v["played"]` |
| 误以为嵌套自动去重 | 列表不自动去重 | 去重用第11章集合或 `not in` 判断 |

## 第 14 章：函数入门 —— 把重复代码打包成"按钮"

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 忘写冒号 `:` | `def` 行必须以 `:` 结尾 | 改成 `def greet(name):` |
| 函数体没缩进 | 函数体必须缩进，否则不属于函数 | 函数体统一缩进 4 个空格 |
| 该用 `return` 却用 `print` | `print` 返回 `None`，结果被丢掉 | 要"接住结果"就用 `return x*2` |
| 默认值参数写前面 | 必填参数不能在选填参数后 | 顺序改成 `def f(base, exp=2)` |
| 以为 `return` 后代码还会跑 | `return` 立刻结束函数 | 把还要执行的代码放 `return` 之前 |
| 把位置参数和关键字参数混淆 | 位置参数顺序重要；关键字参数按名字匹配，顺序不重要 | 位置传参按顺序写；`add(b=3, a=5)` 合法 |

## 第 15 章：作用域与递归初步 —— 函数如何"自己调用自己"

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 忘写 `global` 就想改全局 | **先读后写**（如 `total += 1`）会直接抛 `UnboundLocalError`，并非静默不生效 | 函数内改全局前加 `global total`；只读不改无需声明 |
| 函数外访问局部变量 | 局部变量函数结束就被回收 | 用 `return` 把值交出来再用 |
| 递归没有基线条件 | 永远调自己，直到栈溢出崩溃 | 必须有 `if n==...: return ...` 兜底 |
| 递归不向基线收敛 | 问题越变越大，永远碰不到基线 | 每次调用要让参数"更小/更接近基线" |
| 误以为数字传参会被改 | 数字是不可变对象，外面不变 | 要改就用 `return` 交回新值 |
| 元组/字符串当列表改 | 它们是不可变的，没有改的方法 | 改用可变对象，或返回新字符串 |

## 第 16 章：模块与标准库 —— 不重复造轮子

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 没 import 就用 | `pi` 不在当前命名空间 | 先 `import math` 或 `from math import pi` |
| `from x import *` 污染命名 | 倒进一堆名字，难排查 | 用 `import math` 或精准 `from math import sqrt` |
| 以为 random 真随机 | 是伪随机，可预测 | 密码场景用 `secrets` 库 |
| 添加依赖后绕开项目环境运行 | 运行程序的 Python 环境里没有该依赖 | 在项目目录执行 `uv add 包名`，再用 `uv run 文件名.py` 运行 |
| 别名写错调用 | 起了别名后原名失效 | 统一用别名 `m.sqrt` |
| 抽空列表 | 空列表没东西可抽，报错 | 调用前判断列表非空 |

## Chapter 16A：[错误与异常处理](../functions/exceptions.md)

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 把整个程序都塞进 `try` | `try` 范围过大时，难以判断究竟是哪一步失败 | 只把预期可能失败的少量代码放进 `try` |
| 捕获异常后什么也不做 | `pass` 会让问题悄悄消失，后续还可能因变量未赋值再次失败 | 至少给出提示、返回明确结果，或让用户重试 |
| 用 `assert` 检查外部输入 | 优化模式可能跳过断言，且错误提示不适合用户 | 外部数据用 `if` 校验，失败时提示或 `raise` |

## 第 17 章：算法与效率入门 —— Big-O 直觉

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 以为"能跑出答案就行" | 竞赛限时，慢解=0 分 | 先估 Big-O 再写 |
| 把"少写两行"当优化 | 嵌套层级没变，Big-O 仍是 O(n²) | 优化要降"形状"，非降行数 |
| 混淆 O(n) 和 O(n²) | n 一大就超时百倍 | 想清"每人一次"还是"每人×每人" |
| 忽略"有序"前提就谈效率 | 二分要求有序，乱序会查错 | 先排序或保证有序 |
| 死抠精确次数 | Big-O 本就丢常数 | 只留最高阶项 |
| 只看最好情况 | 运气不总好，最坏才可靠 | 用最坏情况评估 |

## 第 18 章：搜索算法 —— 线性查找与二分查找

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 对乱序数组用二分 | 二分要求有序，乱序砍错方向 | 先排序，或保证数据有序 |
| 循环条件写成 `low < high` | 闭区间 `low==high` 时那个还得查 | 用 `low <= high` |
| `low = mid` 漏了 `+1` | 区间不缩小，永远退不出 | 越过已查的 mid：`mid±1` |
| 中点用 `/` 而非 `//` | 下标必须整数 | 用整除 `//` |
| 二分前忘确认有序 | 有序是二分前提 | 调用前确保已排序 |
| 小数据硬上二分 | 排序开销比直接扫还大 | 小数据/只查一次用线性 |

## 第 19 章：排序算法 —— 冒泡、选择、插入

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 冒泡内层写成 `range(n)` | 已归位的没必要再比 | `range(0, n-1-i)` |
| 选择排序忘更新 `min_idx` | 没记录真正最小的位置 | 比较时更新 `min_idx` |
| 插入排序 `while` 条件漏 `j >= 0` | Python 不报错，却可能拿错误元素继续比较 | 加 `j >= 0` 守卫 |
| 直接改原数组没复制 | 函数副作用难调试 | 开头 `a = a[:]` 复制 |
| 以为"都是 O(n²) 就一样快" | 常数与数据特征差很多 | 看稳定性/有序度来选 |
| 大数据硬用这三种 | O(n²) 撑不住 | 等第20章 O(n log n) |

## 第 20 章：递归与分治（汉诺塔 / 归并 / 记忆化）

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 递归忘了基线条件 | 无限调用直到栈溢出 | 先写 `if 基线: return ...` |
| 归并 `merge` 漏接剩余元素 | 某边先取完，数字丢失 | 合并完务必把两边剩的 `extend` 上 |
| 记忆化 `memo` 每次重建 | 缓存失效，又变慢 | 用默认参数 `memo=None` 在外层建 |
| 汉诺塔柱子角色搞混 | 步骤全错、搬不到目标柱 | 牢记：搬 n-1 时"目标"和"辅助"互换 |
| 以为 `merge_sort` 改原列表 | 原列表还是乱的 | 写成 `data = merge_sort(data)` |

## 第 21 章：基础数据结构（栈 / 队列 / 链表模拟）

| 错误 | 为什么危险 | 立即修正 |
|---|---|---|
| 用 `list.pop(0)` 当队列 | 每次挪动后面所有元素，O(n) | 用 `collections.deque` 的 `popleft()` |
| 栈用错端 | 栈必须从同一端进出（末尾） | 入栈 `append`、出栈 `pop()` |
| 遍历链表后 `cur` 没前进 | 死循环，永远停在第一节 | 循环体里一定 `cur = cur.next` |
| 链表忘了把 `next` 接上 | 链子断成单节，遍历不到 | 建节点后把 `next` 指针串好 |
| `deque` 忘 `from collections import` | 没导入模块 | 文件头加 `from collections import deque` |
